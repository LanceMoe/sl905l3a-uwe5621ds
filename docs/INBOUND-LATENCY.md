# CM311 无线入站延迟排查（2026-10-18）

设备为 CM311-1a YST / UWE5621DS，内核 `6.18.37-ophub`，MTU 1400。
本次改动尚未发布，不改变现有版本号。

## 问题与主要原因

盒子主动 ping 正常，不代表局域网主机访问盒子正常。Windows 通过有线接入，
ping 无线地址时曾测得平均 75–123 ms、最高 596 ms，以及偶发丢包。

`iw` 显示省电关闭，但固件另有 `SET_WLAN_CAP` 休眠能力控制。原驱动的
`set_power_mgmt` 仅发送 `WIFI_CMD_POWER_SAVE`，没有同步该能力。
此外，驱动声明默认省电关闭时，cfg80211 可以跳过重复的关闭回调，
因此只修改回调不足以保证开机状态正确。

在修复 NPI 控制通道后，交替设置源码中的能力值 0、3、0，分别测量 60 个入站包：

| 能力值 | 收到/发送 | 平均 | 中位数 | P95 | 最大 |
| --- | --- | --- | --- | --- | --- |
| 0，首次 | 60/60 | 15.71 ms | 10.90 ms | 24.87 ms | 121.87 ms |
| 3 | 60/60 | 101.75 ms | 60.88 ms | 389.12 ms | 824.41 ms |
| 0，再次 | 60/60 | 16.48 ms | 11.82 ms | 20.79 ms | 122.50 ms |

三个设置均收到固件成功应答。关联 AP 前设置为 0 再重连，60 个入站包
全部收到，平均 14.53 ms。上述可重复对照支持固件休眠能力是主要延迟来源，
但没有消除所有超过 100 ms 的尾部延迟。

这里测的是盒子 eth0 发出以太网帧，经局域网/AP、无线接收后由 AF_PACKET
观察到的单向入站耗时，按 ICMP 标识和序号匹配。它包含交换、AP、无线、
固件、SDIO 和主机接收路径，不能直接当成 Windows 往返时延。
测试没有并行保活流量，也没有安装保活服务。

## 驱动修复

- STA/P2P Client 固件接口初始化时，按 `wdev.ps` 同步休眠能力。
- 运行时修改省电状态，同时同步原省电命令和休眠能力；检查应答类型、子命令、
  长度与固件状态，错误不报告成功。
- 恢复 `ndo_siocdevprivate` 入口；旧 `ndo_do_ioctl` 已不接收现代设备私有命令。
  不支持旧命令结构的兼容 ABI 请求会被拒绝。
- 恢复 NPI family 参数策略及 IFINDEX 类型，要求管理员权限，并拒绝短于命令头的请求。
  实机验证：GET_INFO 返回正确 MAC，非管理员请求返回 EPERM。
- 关闭网卡后再持有 wiphy 锁注销，避免 NETDEV_GOING_DOWN 重复获取该锁。
- 在公共初始化阶段初始化 `remove_done`，避免 Meson 直接注销 SDIO 时操作未初始化的 completion。

测试见 `tests/test_sleep_capability.py`、`tests/test_netdev_lifecycle.py`
和 `tests/test_sdio_remove.py`。这些测试执行实际驱动函数，并用 ASan/UBSan
检查命令格式、错误路径及观测到的退出顺序。

## 验证边界

逐包内核追踪曾发现其他流量等待约 100 ms 的重排定时器；进一步关联 ICMP
序号后，20 个探测包在重排中仅停留 0.024–0.070 ms，不能把那些其他流量
的重排等待直接认定为本次 ping 高延迟的原因。本次没有降低重排超时。

在线卸载先后暴露了 wiphy 自锁和 SDIO completion 异常，均已保存现场并修复。
后续实机验证使用重启，发生过 Oops 的内核不继续加载模块。
初始化与单元测试通过不等于已经证明全部卸载路径、长期稳定性或吞吐正常。

正式补丁安装并重启后，没有发送手动固件设置或保活，60 个单向入站探测包
全部收到，平均 19.88 ms、中位数 11.34 ms、P95 110.64 ms、最大 117.23 ms。
启动日志显示初始化和省电回调均收到休眠能力命令成功应答。
Windows 的往返复测需独立核对，不能由此单向测试替代。


随后进行的 60 包逐包追踪全部收到，平均约 12.16 ms。超过 50 ms 的探测包有 1 个；
这些包的时刻分解见现场 `final-boot/packet-latency-summary.json`。
其中确认存在约 103 ms 的软件重排等待，说明修复主要固件休眠延迟后，
剩余尖峰可以来自另一条路径；本次没有用缩短重排超时掩盖缺帧等待。

用户随后完成 Windows 有线主机到无线地址 `172.16.80.154` 的 60 包复测：
60/60 收到、零丢包，RTT 最小 2 ms、最大 16 ms、平均 7 ms。
相比此前平均 75–123 ms、最高 596 ms，本轮短时局域网往返验证已明显改善。
这是正式补丁重启自动生效后的结果，没有安装保活服务；长期稳定和吞吐仍未由此证明。
