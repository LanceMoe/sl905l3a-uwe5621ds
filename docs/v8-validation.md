# v8 三阶段实机验证

资料：`cm311-linktest-20261017-130111-v8zg0qyn.tar.gz`，2026-10-17。
CM311-1a YST / UWE5621DS，`6.18.37-ophub`，PORT_VERSION=8，采集脚本 v4。
模块加载、原网络连接激活和全部三个阶段完成。全程 MTU 1400、同一 AP、2.4 GHz 信道 11，
802.11 省电 off，信号约 -56 至 -53 dBm。

每阶段 180 秒，同时向网关和公网各每秒发送一个禁止分片的探测，IPv4 总长 1400。
六个 ping 都自行结束，未被采集器终止。总采集约 553.4 秒。

| TX ADDBA 设置 | 网关收到/发送 | 网关 RTT 平均/最大 | 公网收到/发送 | 公网 RTT 平均/最大 |
| --- | --- | --- | --- | --- |
| 三秒重试 | 177/180，丢 1.67% | 151.169/466.234 ms | 177/180，丢 1.67% | 156.977/471.434 ms |
| 暂停新协商 | 154/180，丢 14.44% | 24.394/136.736 ms | 159/180，丢 11.67% | 36.933/154.499 ms |
| 三十秒重试 | 179/180，丢 0.56% | 44.498/477.779 ms | 178/180，丢 1.11% | 38.170/522.722 ms |

网关 RTT 的 90 分位约为 432 → 50.1 → 58.6 ms，公网约 433 → 65.8 → 53.1 ms。
达到 300 ms 的网关回复数量为 57 → 0 → 6；公网为 59 → 0 → 5。
延长间隔后，高延迟回复显著减少，但仍有少数约 400–500 ms 的回复。

## 内核证据

按采集清单的单调时间和 `/proc/uptime` 近似映射内核时间，分别统计三个阶段的新增日志；
未把 `dmesg --follow` 初始回放的历史信息算入新测试。

| 事件 | 三秒重试 | 暂停新协商 | 三十秒重试 |
| --- | ---: | ---: | ---: |
| TX ADDBA 失败回复 | 60 | 0 | 6 |
| RX BA 重排定时器触发 | 3 | 20 | 3 |
| 允许固件休眠的 ACK | 122 | 179 | 173 |
| 主机命令超时 / CP2 复位 / SDIO 新错误日志 | 0 | 0 | 0 |

- 三秒重试阶段 ADDBA 发送到失败回复耗时约 405–419 ms；三十秒阶段约 406–420 ms。
  同期其他命令一般数毫秒到二十毫秒。参数只减少重复失败的尝试，没有让协商成功。
- 起止快照 `sdio_packet_errors` 都是 1，所有阶段快照也均为 1。
  这次持续探测没有新增该类错误，不能写成累计错误为 0。
- `sdio_rx_no_progress` 始终为 0，SDIO 收发与中断计数持续增加，未见接收停滞、
  TX watchdog、掉线或主机命令超时。
- 最后仍连接同一 AP；脚本明确记录 `addba_restore_result=restored`，
  参数文件的结束快照确认 `tx_addba_retry_ms=30000`。

## 结论与保留项

本轮支持“重复失败的协商是明显延迟来源之一”：把三秒改成三十秒，
失败次数从 60 次降至 6 次，同时平均延迟和高延迟回复数量明显减少。
暂停新协商阶段完全没有这类失败，但丢包达到约 12–14%，不能作为默认设置。
保留已经恢复的三十秒默认值，本轮没有依据要求再次更换模块或重启。

这是按固定顺序进行的一轮对照，每个阶段只有三分钟，未随机交替，
不能据此认为丢包差异全由参数导致，也不能声称三十秒是最优间隔。
暂停阶段 RX 重排定时器次数增多是线索，尚不能确认其与每个丢包的因果关系。
固件休眠通知与 `iw power_save` 属于不同机制；后者 off 不代表固件不会休眠。

本机没有 tcpdump，诊断包未包含包捕获；当前信息不能区分丢失的 ICMP 请求/回复
发生在主机发送、固件、空口、AP 还是接收重排阶段。
后续如继续验证，应测本地 TCP 双向传输及更长时间运行；当前尚未测吞吐、
完整 MTU 1500、休眠或蓝牙。v8 可以继续用于 MTU 1400 下的实验使用。
